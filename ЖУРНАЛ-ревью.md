# Журнал ревью

История вердиктов по правкам. Нужен потому, что у проекта нет удалённого
репозитория: вердикт не остаётся в Pull Request, и без записи через месяц никто
не скажет, почему код такой.

**Правила**

- **append-only.** Записи не правятся и не удаляются. Передумали — новая запись
  со ссылкой на старую.
- Записываем и `request changes`: «отклонили» — это тоже факт.
- Обошли hook (`--no-verify`) или приняли исключение из O-правила — пишем здесь
  с причиной. Исключение без записи считается нарушением стандарта.
- Формат и шкала — `REVIEW_STANDARDS.md` §4.4–4.5.

**Находка ревью, закрытая до коммита.** Проверка «нет записи в обход
`atomic_io`» была неполной: `_call_name` возвращал `path.open`, и вызов
методом в усекающем режиме (`path.open("w")`) сторож не видел — то есть
заявление «запись идёт только через `atomic_io`» было сильнее, чем проверка.
Детектор вынесен в `_direct_write_offenders`, научился смотреть на последний
сегмент имени вызова и учитывать позицию режима (у `open(path, "w")` — второй
аргумент, у `path.open("w")` — первый). Дозапись (`"a"`) нарушением не
считается: так ведёт себя лог llama-server, который живой процесс дописывает
в конец. Добавлена проверка `test_detector_sees_direct_writes`, чтобы сторож
не ослеп молча — она дважды поймала ошибку в самом детекторе, пока он
дописывался.

**Принятое изменение поведения (не дефект).** `os.fdopen(..., newline="")`
пишет LF, тогда как прежний `Path.write_text` на Windows давал CRLF. Разбор
JSON, HTML и Markdown от этого не зависит, CSV сохраняет свой терминатор
`\r\n` от `csv.writer`. Отмечено, потому что изменение формата данных без
предупреждения — то, чего стандарт не любит (§5).

**Исключения, которые проверка не ловит и не должна:**
`server_manager.py` дописывает лог сервера в режиме `a`; `config.py` копирует
папку тестов из бандла через `shutil.copytree` (дерево, а не файл).
